1 TP1 - Extreme Programming

Cet exercice d’une heure vous permettra de mettre en pratique les techniques de l’Extreme Programming (XP) en développant un serveur HTTP simple. Vous travaillerez en binômes et utiliserez le développement piloté par les tests (TDD) pour construire votre serveur de manière incrémentale.

Tip

L’objectif n’est pas d’avoir le serveur HTTP le plus complet possible, mais d’expérimenter et maîtriser les techniques XP. Concentrez-vous sur la qualité du process autant que sur le résultat !

1.1 Compétences visées

  • Maîtriser le cycle TDD (Rouge-Vert-Refactoring)
  • Pratiquer la programmation en binôme efficacement
  • Développer de manière incrémentale avec des itérations courtes

2 Mise en place

2.1 Récupération du projet

  • Utilisez ce lien pour créer votre repository Git. Le travail se faisant en binôme, un seul étudiant doit créer la “team”. L’autre doit rejoindre la Team créee.
  • Clonez le repository contenant les classes de base.

Le repository contient :

  • TcpServer.java : Gestion des sockets TCP (fournie)
  • HttpRequestHandler.java : Interface à implémenter (fournie)
  • SimpleHttpServer.java : Classe squelette à compléter

3 Méthode de travail XP

3.1 Programmation en binôme

  • Pilote : Écrit le code, se concentre sur les détails de l’implémentation
  • Copilote : Réfléchit à la stratégie, anticipe les problèmes, suggère des améliorations, consulte la documentation
  • Changement de rôle : Toutes les 15 minutes, ou après chaque itération. Pensez à faire un commit lors du changement

3.2 Cycle TDD strict

Pour chaque fonctionnalité :

  1. 🔴 Rouge : Écrivez un test qui échoue
  2. 🟢 Vert : Écrivez le code minimal pour faire passer le test
  3. 🔵 Refactor : Améliorez le code sans changer le comportement
ImportantRègle d’or du TDD

Ne jamais écrire de code de production sans avoir d’abord un test qui échoue !

4 Spécifications détaillées

Vous allez implémenter la méthode handleRequest(String httpRequest) de l’interface HttpRequestHandler. Cette méthode reçoit une requête HTTP brute et doit retourner une réponse HTTP complète.

4.1 Itération 1 : Réponse HTTP de base

4.1.1 Objectif

Retourner une réponse HTTP valide pour toute requête GET.

4.1.2 Spécifications

  • Accepter une requête HTTP sous forme de chaîne
  • Retourner une réponse HTTP 200 OK avec un contenu HTML simple
  • Inclure les en-têtes obligatoires : Content-Type et Content-Length
  • Gérer les requêtes malformées avec un code 400 Bad Request

4.1.3 Format de sortie attendu

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 27
Server: SimpleHttpServer/1.0

<h1>Serveur HTTP Simple</h1>

4.1.4 Conseils

  • Commencez par le test le plus simple possible
  • Utilisez \r\n comme séparateur de ligne
  • Une ligne vide sépare les en-têtes du corps

4.2 Itération 2 : Analyse des requêtes

4.2.1 Objectif

Parser correctement les composants d’une requête HTTP.

4.2.2 Spécifications

  • Extraire la méthode HTTP (GET, POST, etc.)
  • Extraire le chemin demandé (URI)
  • Extraire la version du protocole
  • Extraire les en-têtes HTTP
  • Traiter les noms d’en-têtes de manière insensible à la casse

4.2.3 Exemple de requête à parser

GET /index.html HTTP/1.1
Host: localhost:8080
User-Agent: Mozilla/5.0

4.2.4 Conseils

  • Créez une classe HttpRequest pour structurer les données
  • Pensez aux cas limites (requêtes malformées)
  • Les en-têtes peuvent contenir des espaces autour des valeurs

4.3 Itération 3 : Serveur de fichiers statiques

4.3.1 Objectif

Servir des fichiers depuis le répertoire public/.

4.3.2 Spécifications

  • Mapper les chemins d’URL vers les fichiers du système
  • Déterminer le Content-Type automatiquement selon l’extension
  • Calculer la Content-Length
  • Gérer l’encoding UTF-8 pour les fichiers texte

4.3.3 Mapping Content-Type requis

Extension Content-Type
.html text/html; charset=utf-8
.css text/css
.js application/javascript
.txt text/plain; charset=utf-8
.png image/png
.jpg, .jpeg image/jpeg
Défaut application/octet-stream

4.3.4 Conseils

  • Utilisez Files.readString() pour les fichiers texte
  • Créez des fichiers de test dans public/ pour vos tests
  • Gérez les chemins relatifs correctement

4.4 Itération 4 : Gestion des erreurs HTTP

4.4.1 Objectif

Retourner les codes d’erreur appropriés.

4.4.2 Codes d’erreur à implémenter

4.4.2.1 404 Not Found

HTTP/1.1 404 Not Found
Content-Type: text/html; charset=utf-8
Content-Length: 47

<h1>404 Not Found</h1><p>Fichier non trouvé</p>

4.4.2.2 405 Method Not Allowed

HTTP/1.1 405 Method Not Allowed
Allow: GET
Content-Type: text/html; charset=utf-8
Content-Length: 64

<h1>405 Method Not Allowed</h1><p>Méthode non supportée</p>

4.4.2.3 400 Bad Request

Pour les requêtes malformées ou dangereuses.

4.4.3 Conseils

  • Seule la méthode GET doit être supportée
  • Créez une méthode pour générer les pages d’erreur
  • Pensez à la sécurité : bloquez les tentatives de path traversal (../)

4.5 Itération 5 : Gestion des répertoires

4.5.1 Objectif

Servir automatiquement index.html pour les requêtes vers des répertoires.

4.5.2 Règles de résolution

  • / → public/index.html
  • /admin/ → public/admin/index.html
  • Si index.html n’existe pas → 404 Not Found

4.5.3 Conseils

  • Détectez les chemins se terminant par /
  • Réutilisez votre logique de service de fichiers existante

5 Test et démonstration

Lancez HttpServer.main.

5.1 Tests manuels

Une fois votre serveur implémenté, testez-le avec : - Navigateur : http://localhost:8080 - curl : curl -v http://localhost:8080/index.html

5.2 Exemples de fichiers de test

Créez dans public/ :

index.html

<!DOCTYPE html>
<html>
<head>
    <title>Mon Serveur HTTP</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>
    <h1>Bienvenue sur mon serveur HTTP !</h1>
    <p>Ce serveur a été développé avec les techniques XP.</p>
</body>
</html>

style.css

body {
    font-family: Arial, sans-serif;
    margin: 40px;
    background-color: #f5f5f5;
}

h1 {
    color: #333;
    border-bottom: 2px solid #007acc;
}

6 Rétrospective (10 min)

À la fin de l’exercice, discutez en équipe :

6.1 Questions de réflexion

  1. TDD : Comment le fait d’écrire les tests en premier a-t-il influencé votre conception ?
  2. Pair Programming : Quels ont été les avantages et défis du travail en binôme ?
  3. Refactoring : À quels moments avez-vous refactorisé ? Qu’est-ce qui vous a motivés ?
  4. Conception simple : Avez-vous résisté à la tentation d’anticiper des besoins futurs ?

6.2 Points d’amélioration

  • Qu’est-ce qui a bien fonctionné dans votre process ?
  • Qu’auriez-vous fait différemment ?
  • Quelles techniques XP avez-vous trouvées les plus utiles ?
