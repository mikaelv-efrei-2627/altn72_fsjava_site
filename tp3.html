TP3 - API REST avec Jakarta EE

1 Installation

  1. Ajoutez la variable d’environnement JAVA_HOME, et pointez là sur un JDK >= 17
  2. Installez Glassfish, server, Web Profile : https://glassfish.org/download.html
    • Il existe plusieurs distributions, appelés “Profile”.
      • Du plus simple au plus complet : Core / Web / Platform. Voir Jakarta EE Services.
      • Nous avons besoin des “RESTful web services” et de “Jakarta persistence”, donc nous choisirons le profile Web
    • Nous utiliserons la version standard server, qui permet de démarrer un serveur d’application sur lequel nous déploierons notre application.
      • Il existe également une version embedded, lorsque l’on souhaite utiliser glassfish comme bibliothèque à intégrer dans un serveur existant.

2 Démarrage

  1. Lancez une invite de commandes, puis allez (cd) dans le répertoire glassfish7/bin
  2. Exécutez startserv.bat
  3. Testez l’installation : http://localhost:8080/
    • Vous devriez voir une page “Your server is now running”.
  4. Lancez la console d’administration : http://localhost:4848
    • Explorez les différents menus.
    • Pouvez-vous expliquer ce qu’est un “JDBC Connection pool” ?
    • Pourquoi aurions-nous besoin d’un pool ?

3 Application Hello World

3.1 Premier déploiement

Nous allons créer une application simple et la déployer sur notre serveur Glassfish.

  1. Dans IntelliJ, File -> New -> Project -> Jakarta EE
  2. name: tp3_hello, location : <à votre convenance>, Template: REST service, No application server, group: org.efrei.altn72, artifact: tp3_hello
  3. Dependencies: CDI, RESTful, Servlet

IntelliJ crée un squelette d’application, qui contient un seul endpoint GET /api/hello-world

  1. Naviguez dans les fichiers sources générés.
  • Question : Pourquoi est-ce que le path complet du endpoint est /api/hello-world ?
  • Question : Quel est le MIME type renvoyé ? (voir What is a MIME type)
  1. Compilez et packagez l’application. Dans IntelliJ, icônes en haut à droite -> maven -> Lifefycle -> package
    • Dans la console, vous devriez voir Building war: C:\...\tp3_hello-1.0-SNAPSHOT.war
  2. Dans l’interface d’administration de Glassfish, allez dans Applications -> Deploy -> Local packaged file -> coller le chemin vers votre .war
    • Context root: hello
    • Laisser le reste par défaut, puis cliquez sur Save.
  3. Testez l’application : http://localhost:8080/hello/api/hello-world
    • Vous devriez voir le message “Hello World!”
      • Question : pourquoi est-ce qu’il faut utiliser le chemin “/hello/api/hello-world” ?
    • Dans votre navigateur, lancez le mode développeur puis allez dans l’onglet “Network”.
    • Rafraîchissez la page
    • À l’aide de l’onglet “Network” répondez aux questions suivantes :
      • Question : quelle est la valeur du header “Content-Type” renvoyé par notre endpoint ?
      • Question : quelle est la valeur du header “X-Powered-By” renvoyé par notre endpoint ?
Tip
  • Un fichier .jar est une “Java Archive”. C’est un fichier compressé au format .zip. Il contient des classes Java compilées. On l’utilise pour distributer des programmes ou des bibliothèques.
  • Un fichier .war est une “Web application Archive”. C’est un format spécifique à Jakarta EE. Il contient tout ce qui est nécéssaire pour déployer une application dans un serveur Jakarta EE. Il contient des fichiers .jar, des pages HTML et images, des fichiers de configuration, …

3.2 Extraire des informations de la requête

Nous souhaitons personnaliser la réponse. Lorsque notre endpoint reçoit la requête HTTP GET /hello/api/hello-word/Ada, il doit répondre avec Hello, Ada.

  • Modifiez le code. Vous devrez ajouter les annotations jakarta.ws.rs.@Path et jakarta.ws.rs.@PathParam. Naviguez dans les sources ou la Javadoc pour comprendre où les ajouter.
  • redéployez vos changements
  • Testez avec http://localhost:8080/hello/api/hello-world/Ada%20Lovelace

4 Application Customer

Nous allons créer une petite application permettant d’enregistrer des clients dans une base de données. Nous exposerons une API REST qui permettra de manipuler (CRUD) des ressources “Customer”.

4.1 Premier déploiement

  1. Dans Moodle, cliquez sur l’invitation Github classroom pour créer votre repository
  2. clonez le repository et explorez le code.
  • Question : quelle requête SQL sera exécutée lorsque nous accèderons à l’endpoint GET /api/customers ?
  1. Générez le fichier .war
  2. Démarrer la base de données Derby.
  • En ligne de commande, allez dans le répertoire glassfish/bin
  • lancez asadmin start-database
  1. Déployez le fichier .war dans votre serveur Glassfish, avec le context root customer
  2. Testez l’endpoint avec http://localhost:8080/customer/api/customers
  • vous devriez voir la liste des clients qui a été insérée par DatabaseInitializer
Tip

Si vous souhaitez accélérer le redéploiement après un changement, vous pouvez installer le plugin IntelliJ Glassfish.

  • Une fois installé, allez dans Services (Alt-8) -> Edit configurations -> New Glassfish Server (Local)
  • Entrez :
    • Name: customer
    • Application server: Configure…
      • GlassFish Home : sélectionner le dossier d’installation glassfish7
    • URL: http://localhost:8080/customer/api/customers
    • Server domain: choisir domain1
  • Fermez le serveur glassfish que vous aviez lancé depuis l’invite de commande
  • Cliquez sur le bouton “Run” dans la fenêtre “Services”
  • Pour redéployer après un changement, cliquez sur “customer” puis l’icône “Update customer application” (Ctrl-F10)

Implémentez l’endpoint en utilisant la méthode findById.

  • Si le client n’existe pas pour cet id, renvoyer un code HTTP 404 Not Found.
  • amélioration : retourner un Optional dans findById, pour éviter de renvoyer null lorsque le client n’existe pas.
Tip

Si vous souhaitez exécuter des requêtes dans la BDD Derby :

  1. Dans IntelliJ, allez dans l’onglet Databases
  2. Cliquez sur New -> Data Source -> Apache Derby
  3. utilisez les paramètres suivants :
    • Driver: Apache Derby (Remote)
    • User: APP
    • Password: APP
    • URL: jdbc:derby://localhost:1527/sun-appserv-samples
  4. Cliquez sur “Test Connection”. Si ça ne fonctionne pas, vérifiez que la base est bien démarrée et que les paramètres sont corrects.

Les paramètres ci-dessus correspondent à ceux visibles dans la console d’administration de GlassFish. Dans GlassFish, voir JDBC -> JDBC Connection Pools -> DerbyPool -> Additional Properties

Implémentez cet endpoint pour pouvoir créer un nouveau client.

  • Il doit recevoir en paramètre des données Json représentant le client.

@POST

@Transactional 
public Response createCustomer(Customer customer) {

    return Response.created(URI.create("/" + customerId)).build();

Tip

L’annotation @Transactional indique au conteneur qu’il faut démarrer une transaction avant la méthode, puis faire un commit ou un rollback à la fin de la méthode. Elle est nécéssaire dès que l’on souhaite effectuer des modifications dans la base de données.

Implémentez cet endpoint pour pouvoir supprimer un client avec son adresse.

  • Si le client n’existe pas pour cet id, renvoyer un code HTTP 404 Not Found.

4.6 Update : Endpoint PUT /api/customers/{id}

Implémentez cet endpoint pour pouvoir mettre à jour un client et son adresse.

  • Si le client n’existe pas pour cet id, renvoyer un code HTTP 404 Not Found.
  • Utilisez em.merge pour effectuer la mise à jour.
  • Renvoyer le code HTTP 200 OK si la mise à jour a pu être effectuée.

4.7 Validation

Lire cette page : Bean Validation, puis ajouter les validations suivantes :

  • l’email doit être valide
  • phone ne doit pas dépasser 30 caractères et doit être composé de chiffres, commencer par +, et peut contenir des espaces ou des tirets.
  • name et firstname ne doivent pas dépasser 50 caractères

Si l’un des champs n’est pas valide, renvoyer un code HTTP 400 BadRequest.

4.8 Update partiel : Endpoint PATCH /api/customers/{id}

Dans une API RESTful, le verbe PATCH permet de modifier une ressource partiellement.

Si j’envoie une requête PATCH /api/customers/2 avec ce corps :

{
  "email": "pierredupont@example.fr",
  "phone": "+33-1-42-34-56-78"
}

Le client sera mis à jour avec ces informations, et les autres champs ne doivent pas être modifiés. A la différence de PUT, je n’ai pas besoin d’envoyer tous les champs, j’envoie uniquement ceux que je souhaite modifier.

4.9 Refactoring

Ce code est simplifié et possède un couplage fort entre :

  • la base de données et l’API REST : les mêmes classes sont utilisées
  • le controlleur REST et les services métier : le controlleur accède directement à l’EntityManager

Modifiez le code pour découpler ces deux aspects :

  • Introduire une classe CustomerService.
    • Elle aura l’annotation @Stateless et sera injectée dans CustomerResource avec l’annotation @Inject.
    • Elle manipule uniquement des classes @Entity
  • Introduire des classes DTO (Data Transfer Object), qui seront utilisées dans CustomerResource.
  • CustomerResource doit convertir les classes DTO en classes Entity, et appeler CustomerService.
