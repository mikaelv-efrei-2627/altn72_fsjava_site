TP5 - API REST avec Spring Boot

Gestion d’une billetterie de concerts

1 Introduction

1.1 Objectifs du TP

Ce TP vous permettra d’implémenter une fonctionnalité complète dans une application Spring Boot : la gestion des billets de concert. Vous allez parcourir toutes les couches de l’architecture :

  • Créer un Repository Spring Data JPA avec des query methods
  • Implémenter un Service avec logique métier et validation
  • Créer des DTOs pour l’API REST
  • Développer un Contrôleur REST avec plusieurs endpoints
  • Écrire des tests JUnit pour valider votre implémentation

1.2 Technologies utilisées

  • Spring Boot 3.5.8
  • Spring Data JPA
  • Spring Web
  • Base de données H2 (en mémoire)
  • JUnit 5 + Spring Boot Test + MockMvc
  • Mockito
  • Maven

9 Partie 7 : Tests unitaires du Service

9.1 Approche cohérente avec Spring Boot Test

Vous avez écrit des tests de contrôleur avec @WebMvcTest + @MockitoBean. Pour les tests de service, nous utilisons la même approche Spring Boot avec @SpringBootTest + @MockitoBean.

Tests de contrôleur (@WebMvcTest) :

  • Testent les endpoints REST avec MockMvc
  • Vérifient la sérialisation JSON et les codes HTTP
  • Mockent la couche service avec @MockitoBean

Tests de service (@SpringBootTest) :

  • Testent la logique métier du service
  • Vérifient les validations et transformations
  • Mockent la couche repository avec @MockitoBean
ImportantApproche uniforme

Dans les deux cas, on utilise Spring Boot Test (@WebMvcTest ou @SpringBootTest) avec @MockitoBean pour mocker la couche en dessous. On aurait pu utiliser Mockito directement pour les services, mais c’est plus uniforme comme cela.

9.2 Examiner ArtistServiceTest

Un exemple complet est fourni dans ArtistServiceTest.java. Examinez ce fichier pour comprendre :

  • @SpringBootTest - Charge le contexte Spring pour tester le service
  • @MockitoBean - Crée un mock du repository (remplace le vrai bean dans le contexte)
  • @Autowired - Injecte le vrai service (qui utilisera les mocks)
  • when().thenReturn() - Définit le comportement des mocks (comme dans les tests de contrôleur)
  • verify() - Vérifie que les méthodes ont été appelées
  • AssertJ (assertThat()) - Assertions fluides

Structure d’un test de service :

@SpringBootTest
class ArtistServiceTest {
    @MockitoBean
    private ArtistRepository artistRepository;

    @Autowired
    private ArtistService artistService;

    @Test
    void shouldReturnAllArtists() {
        // Given - Préparer les données et configurer les mocks
        Artist artist = new Artist("The Rolling Stones", "Rock", "UK");
        when(artistRepository.findAll()).thenReturn(List.of(artist));

        // When - Appeler la méthode à tester
        List<ArtistDTO> result = artistService.getAllArtists();

        // Then - Vérifier les résultats
        assertThat(result).hasSize(1);
        assertThat(result.get(0).name()).isEqualTo("The Rolling Stones");
        verify(artistRepository, times(1)).findAll();
    }
}

TipConseils pour les tests de service
  • Utilisez Spring Boot Test : Avec @SpringBootTest + @MockitoBean, c’est cohérent avec les tests de contrôleur
  • Isolez avec les mocks : @MockitoBean remplace les vrais repositories par des mocks
  • Testez tous les cas : Succès, erreurs, cas limites (concert complet, entités inexistantes)
  • Vérifiez les appels : Utilisez verify() pour confirmer que les repositories sont appelés correctement
  • Pensez aux exceptions : Utilisez assertThatThrownBy() pour tester les cas d’erreur
  • Même syntaxe que les tests de contrôleur : when().thenReturn() et verify() fonctionnent exactement pareil !

10 Pour aller plus loin

10.1 Gestion des erreurs

Améliorez la gestion d’erreurs :

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, String>> handleIllegalArgument(
            IllegalArgumentException ex) {
        Map<String, String> error = Map.of(
            "error", "Bad Request",
            "message", ex.getMessage()
        );
        return ResponseEntity.badRequest().body(error);
    }

    @ExceptionHandler(IllegalStateException.class)
    public ResponseEntity<Map<String, String>> handleIllegalState(
            IllegalStateException ex) {
        Map<String, String> error = Map.of(
            "error", "Conflict",
            "message", ex.getMessage()
        );
        return ResponseEntity.status(HttpStatus.CONFLICT).body(error);
    }
}
