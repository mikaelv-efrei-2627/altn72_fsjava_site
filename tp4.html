TP4 - Jakarta Persistence

Gestion d’une billeterie de concerts

1 Introduction

1.1 Objectifs du TP

Ce TP vous permettra de maîtriser les concepts fondamentaux de Jakarta Persistence (JPA) en construisant une application de gestion de billeterie de concerts. Vous allez :

  • Modéliser des entités avec différents types de relations
  • Configurer Jakarta Persistence avec une base de données H2
  • Écrire et exécuter des requêtes JPQL complexes
  • Manipuler des entités avec l’EntityManager

1.2 Technologies utilisées

  • Jakarta Persistence API 3.2
  • Hibernate 7.1 (implémentation)
  • Base de données H2 (en mémoire)
  • Maven

2 Configuration du projet

Utilisez le lien GitHub Classroom pour créer votre repository, puis clonez le et importez le dans IntelliJ. Le projet contient :

  • dans pom.xml, les dépendances nécéssaires pour Hibernate et Jakarta persistence
  • dans persistence.xml, la configuration de la persistence unit concert-pu.

3 Modélisation des entités

Vous allez créer 4 entités avec différents types de relations :

  • Artist (Artiste) : représente un artiste ou groupe musical
  • Concert : représente un événement de concert
  • Ticket : représente un billet pour un concert
  • Customer (Client) : représente un acheteur de billets

3.1 Relations entre entités

Le schéma des relations est le suivant :

  • Artist ↔︎ Concert : Un artiste peut donner plusieurs concerts (OneToMany / ManyToOne)
  • Concert ↔︎ Ticket : Un concert a plusieurs billets (OneToMany / ManyToOne)
  • Customer ↔︎ Ticket : Un client peut acheter plusieurs billets (OneToMany / ManyToOne)
Tip

Pensez à utiliser @ManyToOne côté “plusieurs” et @OneToMany côté “un”. La clé étrangère sera stockée dans la table du côté @ManyToOne.

3.3 Créer l’entité Artist

Créez la classe Artist.java dans le package concert.entity.

Attributs à créer :

  • id : Long, clé primaire avec génération automatique (IDENTITY)
  • name : String, obligatoire, longueur max 100
  • genre : String, longueur max 50
  • countryOfOrigin : String, nom de colonne “country_of_origin”, longueur max 50
  • concerts : List, relation OneToMany bidirectionnelle avec cascade ALL

Annotations de persistance :

  • Annotation @Entity sur la classe
  • Annotation @Table(name = "artist") pour le nom de la table
  • Pour la relation OneToMany : mappedBy = "artist" (fait référence à l’attribut dans Concert)

Constructeurs à créer :

  • Un constructeur vide (requis par Jakarta persistence)
  • Un constructeur avec paramètres : name, genre, countryOfOrigin
  • N’oubliez pas d’initialiser la liste concerts dans les constructeurs : this.concerts = new ArrayList<>()

Méthode helper :

public void addConcert(Concert concert) {
    concerts.add(concert);
    // il faut mettre à jour l'autre côté de la relation
    concert.setArtist(this);
}
Note

Pour chaque classe entité,

  • Pensez à importer les classes nécessaires : jakarta.persistence.*, java.util.ArrayList, java.util.List
  • Utilisez IntelliJ (Code -> Generate …) pour générer :
    • les constructeurs
    • les getters
    • les setters, SAUF pour les id et les List
      • les id ne doivent jamais changer et sont générés
      • les List sont instanciées dans le constructeur. On doit pouvoir ajouter/supprimer des éléments, mais pas remplacer la liste complète.
      • les setters sur des relations @OneToMany doivent être protected
        • ils doivent uniquement être appelé par les méthodes addXXX de l’autre côté de la relation
    • une méthode toString (omettre les attributs de type List ou annotés @Entity)

3.6.2 Entité Ticket

Créez la classe Ticket.java dans le package concert.entity.

Attributs à créer :

  • id : Long, clé primaire avec génération automatique (IDENTITY)
  • ticketNumber : String, obligatoire, unique, longueur max 50
  • category : TicketCategory (énumération), obligatoire, stocké en STRING
  • price : BigDecimal, obligatoire, précision 10, échelle 2
  • purchaseDate : LocalDateTime, nom de colonne “purchase_date”
  • seatNumber : String, longueur max 50 (peut être null pour les billets debout)
  • concert : Concert, relation ManyToOne avec jointure sur “concert_id”
  • customer : Customer, relation ManyToOne avec jointure sur “customer_id”

Annotations

  • Annotation @Entity et @Table(name = "tickets")
  • Pour l’énumération : @Enumerated(EnumType.STRING) (stocke le nom au lieu d’un nombre)
  • Pour le prix : @Column(nullable = false, precision = 10, scale = 2)
  • Pour les ManyToOne : @JoinColumn(name = "concert_id") et @JoinColumn(name = "customer_id")

Constructeurs à créer :

  • Un constructeur vide
  • Un constructeur avec : ticketNumber, category, price, seatNumber
    • Dans ce constructeur, initialisez purchaseDate à LocalDateTime.now()

7.1 Tests unitaires

Ecrire un test unitaire pour ConcertRepository. Utilisez ce pattern pour initialiser la base et l’EntityManager :

import jakarta.persistence.EntityManager;
import jakarta.persistence.EntityManagerFactory;
import jakarta.persistence.Persistence;
import org.junit.jupiter.api.*;

@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class PersistenceTest {

    private static EntityManagerFactory emf;
    private EntityManager em;

    @BeforeAll
    void setUpAll() {
        // Initialize the persistence unit once for all tests
        emf = Persistence.createEntityManagerFactory("concert-pu");
    }

    @BeforeEach
    void setUp() {
        // Create a new EntityManager for each test
        em = emf.createEntityManager();
    }

    @AfterEach
    void tearDown() {
        // Clean up after each test
        if (em != null && em.isOpen()) {
            if (em.getTransaction().isActive()) {
                em.getTransaction().rollback();
            }
            em.close();
        }
    }

    @AfterAll
    void tearDownAll() {
        // Close the factory after all tests
        if (emf != null && emf.isOpen()) {
            emf.close();
        }
    }
}

7.6 Criteria API

Alternative typée et programmatique à JPQL :

ConcertRepository.java
public class ConcertRepository {
    // (...)

    public List<Concert> criteriaApiExample(String city) {
        try (EntityManager em = emf.createEntityManager()) {
            CriteriaBuilder cb = em.getCriteriaBuilder();
            CriteriaQuery<Concert> cq = cb.createQuery(Concert.class);
            Root<Concert> concert = cq.from(Concert.class);

            cq.select(concert)
              .where(cb.equal(concert.get("city"), city));

            return em.createQuery(cq).getResultList();
        }
    }
}
